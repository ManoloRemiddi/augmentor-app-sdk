# __APP_NAME__ agent integration

Generated by `augmentor-app init --template app`. Read the SDK's docs/GUIDE.md first.

1. Implement `records` (read, update with version check, share) in your server and pass it
   to `createAgentServer()` from `augmentor/server.mjs`, with your owner-session check.
2. Route requests: `if (await agent.node(req, res)) return;` before your own routes, and
   forward WebSocket upgrades with `agent.upgrade(req, socket, head)`.
3. In your page, call `startAgent()` from `augmentor/page.mjs`. Mark elements the agent may
   highlight with `data-augmentor-key="record:42"` and add "Ask" buttons with
   `data-augmentor-prompt="summarize_record" data-augmentor-vars='{"id":"42"}'`.
4. After editing `augmentor/app.mjs`, run `augmentor-app manifest augmentor/app.mjs`, then
   `augmentor-app check augmentor/app.mjs`.
5. Create the private configuration (SDK docs/QUICKSTART.md section 4): make an ignored
   `augmentor/private/` folder (mode 700), a random runtime token file in it (mode 600), and copy
   `install.example.json` to `augmentor/private/install.json`. Set `origin` to the app's exact
   origin and use absolute paths: `toolConfig.<plugin>.tokenFile` is the runtime token your
   server also reads (`runtimeTokenFile`), and `tokenFile` is the panel-proxy token that
   `register` creates and your server reads (`proxyTokenFile`). Never commit either token.
6. On the machine running Augmentor: `augmentor-app validate augmentor.app.json`, then
   `augmentor-app plan augmentor.app.json augmentor/private/install.json`, review it, then
   `augmentor-app register …` with the same arguments. Registration does not restart
   anything; new or changed tools load the next time Augmentor starts (quit and reopen it,
   or its next update). Open a **new chat** in the app's panel afterwards.
7. The "Ask" buttons send the prompt into the open chat when the Augmentor panel supports it
   (builds that include augmentor-agent#43); otherwise they run it in the background on your
   server (`background: true`, the default) and show a notice.

Generated files are a starter, not evidence that a deployment works. Follow docs/ACCEPTANCE.md.
