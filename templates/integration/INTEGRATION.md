# Integration scaffold: __APP_ID__

This is application-owned wiring, not a finished application or independent SDK
adoption test. It requires the installed `@augmentor/app-sdk` dependency and a
compatible managed Linux Augmentor runtime. No credentials, registration,
runtime changes or model calls were created by `init`.

1. Read the SDK's `docs/AGENT-INTEGRATION.md`, `docs/QUICKSTART.md` and
   `docs/ACCEPTANCE.md` (also shipped in `node_modules/@augmentor/app-sdk/docs/`).
2. Review the root `augmentor.app.json` and this directory's role. The only
   declared tool is `__TOOL_NAME__`. No extra runtime tools are granted.
3. Connect `server.mjs` to your existing HTTP and WebSocket routers. Supply your
   actual owner-session validator and `readRecord(id)` backed by authoritative
   application records. Return `{id, version, title}` or `null`. Adapt this small
   projection and the tool's output schema together for your domain. If private
   installation options override `id`, pass that workspace ID as `profile` to
   `createAppIntegration`; it defaults to the manifest ID.
4. Bundle `browser.mjs` through your normal frontend build. Mount in a container
   with a real height, forward selected-record IDs with `setContext`, and call
   `destroy()` on teardown. Do not recreate the chat UI.
5. Create separate private app-agent and proxy credentials, using the quick
   start. Copy `install.example.json` to `private/install.json`, replace every
   placeholder with this installation's actual values, and keep that directory
   ignored and mode 0700. Keep credential files mode 0600. The proxy token is
   generated by `register`; the backend generates/validates the app-agent token.
6. Run the locally installed CLI: `./node_modules/.bin/augmentor-app validate
   augmentor.app.json`, then `doctor`, then `plan augmentor.app.json
   augmentor/private/install.json`. Review the exact grants and stable identity
   before registering. `plan` is read-only and does not certify a running host.
7. Register on the Augmentor model host, start your application through its normal
   launcher, and run the acceptance checklist with a new chat. Preserve existing
   histories and data; an older instantiated agent is not retroactively recomposed.

Do not add writes until the application owns revision checks, stable operation
and domain identities, durable receipts, uncertain-outcome reconciliation and
any required send/publish approval. Tool completion does not prove task quality.
